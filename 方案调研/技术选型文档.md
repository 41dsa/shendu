## 1. 选型目标与原则

### 1.1 业务目标对齐（产品能力不变）

V1 核心闭环与 PRD **功能验收** 对齐（Web 端实现），**批改对象明确为申论大作文**（完整议论文），**不包含**小题型的「读材料概括 / 综合分析 / 提出对策」作答形态：

- **AI 批改（大作文）**：维度化评分（立意、结构、论证、语言等）、规则预评、**多模型共识**（可分层触发）、**置信度**、失分诊断、修改建议、评分依据与争议入口。
- **教练闭环**：二次作答、问题本、能力画像、训练推荐。
- **教研最小闭环**：大作文题干 / 可选参考背景 / 评分维度 / 金标 / Prompt 版本。

**范围收缩（相对 PRD）**：


| PRD           | V1.3                              |
| ------------- | --------------------------------- |
| Web + Android | **仅 Web**（移动端用浏览器响应式，不做应用商店与 IAP） |
| 平台承担 AI 成本    | **BYOK**；设置页展示预估 Token/费用         |
| 会员订阅          | **不做**；**买断**（通过爱发电档位 + 激活码交付）    |


### 1.2 商业与收款（V1.3 定稿）


| 维度           | 方案                                                                    |
| ------------ | --------------------------------------------------------------------- |
| 卖什么          | **软件永久使用权**（License）；不含模型 API 费用                                      |
| AI 费用        | 用户自备 API Key，自行向 DeepSeek / 通义等充值                                     |
| **短期收款（必做）** | **[爱发电](https://afdian.net)**：设 **一次性赞助档位**（如「永久激活」），平台代收；**无需企业商户号** |
| **交付方式**     | 爱发电 **自动/手动私信** 发放 **激活码** → 用户在 Web **登录后兑换** → 写入 `licenses`        |
| 主站支付 API     | **V1 不接** 微信/支付宝商户回调                                                  |
| 后续演进         | 注册个体户/公司后，可 **保留兑换码** 并 **追加** 站内扫码支付（见 §4.5）                         |


**爱发电侧产品约定（运营配置，非代码）**：

- 档位名称明确为「AI申论教练 · 永久激活码」一类，避免与「月度赞助」混淆。
- 发货文案固定模板：激活码 + 兑换 URL + 「一码一号、勿泄露」+ BYOK 说明链接。
- 购买前说明：需自备模型 API Key；软件买断不含 AI 充值。

### 1.3 修订原则

1. **收钱在爱发电，授权在主站**：主站只做 **鉴权与兑换**，降低个人合规与接入成本。
2. **平台不为 LLM 买单**：无平台统一 API Key 池。
3. **买断与 BYOK 分离**：无 License → 不可用核心功能；有 License 无 Key → 不可批改。
4. **单栈、轻部署**：FastAPI + Celery + Docker Compose。
5. **密钥安全 P0**：BYOK 服务端 AES-GCM Vault，日志脱敏。

## 3. 爱发电买断 + License（核心）

### 3.1 用户旅程

```text
1. 访问 Web → 注册/登录
2. 未激活 → 「购买」页：说明 + 按钮跳转爱发电指定档位（新窗口）
3. 爱发电付款成功 → 收到激活码（私信/邮件/档位附赠，依爱发电配置）
4. 回到 Web → 「激活」页输入激活码 → POST /redeem
5. 成功 → licenses.active → 引导配置 BYOK → 开始批改
```

### 3.2 爱发电履约方式（推荐组合）


| 方式                         | 做法                                                         | 自动化程度 |
| -------------------------- | ---------------------------------------------------------- | ----- |
| **A. 批量预生成码（推荐 V1）**       | 后台生成 N 个码入库；爱发电档位说明「付款后私信发码」；你或脚本根据 **爱发电订单通知**（邮件/后台）人工发码 | 半自动   |
| **B. 一订单一码**               | 收到爱发电 **订单号后四位 + 赞助邮箱**，admin 绑定生成码或从池分配                   | 人工    |
| **C. 爱发电 API/Webhook（P1）** | 若开通能力：付款成功 → 服务端自动从码池 **取 unused 码** 并通过爱发电 API 私信         | 全自动   |


**V1 默认 A + B**：实现快；码池低于阈值告警，避免卖超。

**幂等**：同一 `redeem_code` 只能绑定 **一个** `user_id`；重复兑换返回明确错误。

### 3.3 数据模型

`**products`（可选，单 SKU 可硬编码）**

```text
sku              lifetime_web
name             AI申论教练永久版（Web）
afdian_plan_url  爱发电档位链接（配置项）
```

`**redeem_codes**`

```text
code             PK  建议 12～16 位，大写字母+数字，去歧义字符
sku              lifetime_web
status           unused | used | revoked
used_by_user_id  FK nullable
used_at
batch_id         生成批次，便于追溯
note             可选：afdian_order_hint
```

`**orders`（V1 简化：记录兑换来源，非支付网关）**

```text
id
user_id
sku
channel          afdian_redeem | admin_grant
external_ref     激活码 或 爱发电订单备注
status           completed
created_at
```

`**licenses**`

```text
user_id          UNIQUE（V1 一用户一条 active）
sku              lifetime_web
status           active | revoked
source           redeem_code | admin
source_ref       redeem_codes.code 或 admin 操作 id
valid_until      NULL（终身）或合同年限
activated_at
revoked_at
```

### 3.4 API 与中间件


| 接口                    | 说明                                                 |
| --------------------- | -------------------------------------------------- |
| `GET /me/entitlement` | `{ licensed, sku, activated_at }`                  |
| `POST /redeem`        | body: `{ code }`；事务：码 unused→used + upsert license |
| `GET /purchase`       | 静态：爱发电链接、购买说明、FAQ                                  |


**受保护路由**（需 `license.status == active`）：

- `POST /submissions`, `POST /grading-jobs`, `POST /trainings/*` 等写操作  
- 读历史报告是否开放给未付费用户：**建议仅允许 demo 题或 0 条**，产品定

**BYOK 门禁**（批改链）：另有 `user_provider_credentials` 主模型配置。

### 3.5 管理端（必做）


| 功能                      | 说明                 |
| ----------------------- | ------------------ |
| 批量生成激活码                 | 导出 CSV；可打印贴爱发电发货模板 |
| 码池统计                    | unused 数量、低于 N 告警  |
| 手动 grant/revoke License | 客诉、补发、退款           |
| 绑定备注                    | 记录爱发电订单号便于对账       |


### 3.6 后续：主体就绪后追加支付（不推翻 V1）

- 保留 **兑换码** 与爱发电档位并行。
- 新增 `channel=wechat|alipay` 的 `orders` + 支付回调 → 可 **自动发码** 或 **直接写 license**。
- 爱发电可作为长期备用渠道。

## 4. BYOK 技术方案（摘要）

与 V1.2 一致，Web-only 下更简单：


| 配置项  | 必填        | 说明                               |
| ---- | --------- | -------------------------------- |
| 主模型  | **是**     | `base_url` + `api_key` + `model` |
| 共识模型 | 否         | 未配置则同 Key 多 Prompt 共识            |
| OCR  | **V1 不做** | Web 以粘贴/输入为主                     |
| 连接测试 | 建议        | 通过后方可提交批改                        |


存储：**AES-256-GCM** 表 `user_provider_credentials`；Worker 内存解密调用；禁止日志输出 Key。

多模型共识、合并调用、分层触发：同 V1.1/V1.2，费用由用户在厂商侧承担。

## 12. 风险与缓解


| 风险            | 缓解                                      |
| ------------- | --------------------------------------- |
| 爱发电规则变更       | 购买页注明渠道；预留 admin grant；后续加个体户直连支付       |
| 码泄露/转卖        | 一码一号；异常批量兑换告警；可 revoke 码                |
| 付款未收到码        | FAQ + 客服邮箱；后台按爱发电订单补发                   |
| 个人经营合规        | 爱发电代收；主页用户协议/隐私政策；软件说明与 BYOK 免责声明       |
| 服务器存 Key      | 加密 Vault、HTTPS、日志脱敏                     |
| PRD 写 Android | 以本文 **Web-only** 为 V1 研发基线，Android 列 P2 |


---

## 13. 结论

**V1.3** 在 **无企业主体、短期必须收钱** 条件下，采用 **爱发电站外收款 + 主站激活码兑换 License**，避免微信/支付宝商户接入；**仅 Web** 降低适配成本；**BYOK** 避免平台 AI 变量成本。研发重点：**兑换幂等、码池管理、License/BYOK 双门禁、批改管线**；支付自动化可在爱发电 API 可用时再升级。
