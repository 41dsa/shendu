## 1. 设计原则（继承 V0.1 设计文档）

1. **控制复杂度**：先跑通「一套大作文标准如何生成、验证、发布、被批改消费」最小闭环，再扩省考卷种与题量。
2. **可验证、可迭代**：标准不是一次性「完美 Prompt」，而是带版本、置信度、溯源的发布物。
3. **模块 ≠ Agent**：八个逻辑模块由 **确定性编排 + 分步 LLM 任务** 实现，避免多 Agent 失控。
4. **与产品 V1 一致**：**BYOK**、**Web-only**、平台不为 LLM 买单；标准生成主要在 **教研 / Admin** 侧触发（可用管理员 BYOK 或教研专用 Key，与现有 `admin_research` 金标跑分一致）。

## 2. V0.1-E 目标与边界

### 2.1 不追求（本期不做）

| 不做什么 | 原因 |
|----------|------|
| 覆盖全部省考卷种与命题风格 | 先验证「标准生成 + 验证」方法论 |
| 自动生成不可审计的「黑盒总分公式」 | 总分 = 各维度权重之和，规则透明 |
| 小题采分点（SP001 材料要点） | 产品 V1 批改对象仅为**大作文** |
| 完整用户能力画像引擎 | 属教练闭环（P5+），非标准引擎核心 |
| LangChain / LangGraph 编排 | 增加依赖与调试成本；V0.1 用 Celery 步骤机即可 |

### 2.2 核心验证目标

输入：**一套申论大作文真题信息**（题干、作答要求、可选参考背景、公开解析/范文等），系统能否自动生成 **结构化、可验证、可用于 AI 批改** 的 **题目标准 + 维度 Rubric + 失分规则**，且置信度与验证项可解释。

### 2.3 核心闭环

```text
真题与参考资料 → 资料解析 → 大作文题结构化 → 题目标准生成 → 维度 Rubric 生成
    → 标准验证 → 标准发布 → 作答评价引擎拉取标准 → 用户批改
```

### 2.4 考试范围建议（V0.1-E）

| 维度 | 建议 |
|------|------|
| 题量 | **30～80 道** 大作文（国考 + 2～3 个高频省考），低于小题 100～300 的规模 |
| 时间 | **2024～2026** 真题为主 |
| 分值 | 以卷面 **35～50 分/题** 为主，维度划分与 `word_min/word_max` 随卷配置 |
| 并行 | **不** 同时铺开六省 + 国考；先 **国考副省级/市地级大作文** 一类跑通 |

## 3. 双引擎产品边界

与 V0.1 设计文档 §10 一致，对象映射如下：

```text
┌─────────────────────────────────────────────────────────────────┐
│  AI 考试标准引擎（应如何评价）                                      │
│  考试级规范 · 大作文题型标准 · 题目标准 · 维度 Rubric · 失分规则      │
└───────────────────────────────┬─────────────────────────────────┘
                                │ 标准服务（M8）
                                │ 返回 QuestionStandard + RubricStandard
                                │       + ScoringRules + LossRules
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│  AI 作答评价引擎（这篇答得怎么样）— 现网 grading_service           │
│  答案理解 · 维度命中 · 评分 · 失分诊断 · 修改建议 · 共识/置信度      │
└───────────────────────────────┬─────────────────────────────────┘
                                │
                                ▼
                     教练：二次作答 · 能力 · 训练推荐
```

**耦合规则**：

- 评价引擎 **只读** 已发布标准（`status=published` + 指定 `version`）；禁止在批改路径里临时改 Rubric。
- 标准引擎 **不** 读取用户作文；用户答案匹配（Prompt 06）可在评价引擎内实现，但 **匹配依据** 必须来自标准引擎输出的 Rubric 与失分规则。

## 4. 整体架构

### 4.1 逻辑分层

```text
┌──────────────────────────────────────────────────────────────────┐
│  apps/web — 教研扩展（Admin）                                       │
│  资料上传 · 生成任务进度 · 标准预览/ diff · 发布 · 版本回滚              │
└────────────────────────────┬─────────────────────────────────────┘
                             │ HTTPS /api
┌────────────────────────────▼─────────────────────────────────────┐
│  services/api — FastAPI                                           │
│  ┌─────────────────┐  ┌──────────────────────────────────────┐ │
│  │ 现有：auth/license │  │ standard_engine（新增域）              │ │
│  │ byok/grading/…   │  │ ingest · parse · structure · generate │ │
│  └─────────────────┘  │ validate · publish · standard_query    │ │
│                        └──────────────────────────────────────┘ │
└────────────────────────────┬─────────────────────────────────────┘
                             │
         ┌───────────────────┼───────────────────┐
         ▼                   ▼                   ▼
   PostgreSQL            对象存储（可选）         Celery Worker
   exam_standards…       原始 PDF/Word          standard_generation_job
                             │
                             ▼
                    用户/教研 BYOK → httpx chat/completions
```

### 4.2 八模块映射（大作文语义）

| 模块 | 名称 | 大作文职责 |
|------|------|------------|
| M1 | 资料管理 | 大纲、大作文评分说明、真题题干、参考背景、公开范文/解析；**来源分级 S/A/B/C** |
| M2 | 文档解析 | PDF/Word/HTML/TXT → 统一 `Document`；保证题号、字数要求、材料顺序 |
| M3 | 真题结构化 | `Paper` → **EssayQuestion**（题干、要求、字数、分值、可选 material） |
| M4 | 题目标准生成 | **QuestionStandard**：命题类型、审题任务、立意方向、体裁、篇章结构期望、能力维 A1～A5 |
| M5 | Rubric 生成 | **RubricStandard**：按维度生成 **RubricCriterion**（语义单元，非关键词） |
| M6 | 标准验证 | 范文覆盖、维度一致性、重复项、分值求和、题干约束可追溯 |
| M7 | 标准发布 | 版本、状态（draft/review/published/archived）、生效绑定 `question_id` |
| M8 | 标准服务 | `GET` 活跃标准；供 `grading_service` 拉取 Rubric 与规则 |

> **术语对照**：V0.1 小题文档中的「采分点 ScoringPoint」在大作文中落实为 **RubricCriterion（维度下的评分语义单元）**；卷面「维度 D01～D04」与能力 **A1～A5** 见 [`app/domain/essay.py`](../services/api/app/domain/essay.py)。

### 4.3 标准生成主流程（编排）

采用 **状态机 + Celery 链**（与 `grading_job` 类似），一步一持久化，便于重试与审验：

```text
standard_job: pending → ingest_done → structured → question_std_done
           → rubric_candidates → rubric_merged → validated → published | failed
```

每一步：

- 输入/输出写入 `standard_job_steps`（JSON）；
- LLM 调用经 `ai_client`（与批改相同 BYOK 解密路径）；
- 输出经 **Pydantic 模型校验**，失败则本步重试（上限 N 次）或标记 `needs_review`。

## 5. M1～M7 模块要点

### M1 资料管理与溯源

| 类别 | 内容 |
|------|------|
| A 考试资料 | 国考/省考申论大纲中与大作文相关条款 |
| B 真题 | 题干、作答要求、分值、字数 |
| C 参考资料 | 官方解析、出版社范文、机构参考答案（**B/C 级**） |

每个 **RubricCriterion** 必须可附 `source_refs[]`（document_id + excerpt），满足「结论来自哪里」。

### M2 文档解析

- **V0.1 选型**：`pymupdf`（PDF 主）、`python-docx`（Word）、`beautifulsoup4` + `lxml`（HTML）、纯文本直读。
- **不做**：知识图谱、OCR（与产品 V1 一致）。
- 输出统一 `Document`（见 [数据契约](./数据契约-V0.1-大作文.md)）。

### M3 大作文题结构化

EssayQuestion 最小字段：`question_no`、`prompt`、`requirements`、`word_min`、`word_max`、`score`、`material_optional`、`exam`、`year`、`paper_id`。

与现网 `Question` 对齐：`question_type=essay`，`material_structured` 存字数与考试元数据。

### M4 题目标准生成（LLM #1）

拆解链（大作文版）：

```text
题型(essay) → 命题形式(话题/命题/漫画…) → 审题任务 → 立意边界 → 篇章结构期望 → 能力重点
```

示例：「围绕『基层治理』写一篇文章」→ 需明确：是否**联系实际**、是否**对策为主**、分论点数量期望、是否必须扣材料背景等。

### M5 Rubric 生成（核心，两步法）

**第一步 — 候选准则（LLM #3）**  
输入：QuestionStandard + 材料摘要（若有）+ 参考范文/解析  
输出：各维度下多条 **候选 RubricCriterion**（含 `core`、`observable_signals`、`typical_gaps`）。

**第二步 — 合并与过滤（LLM #4）**  
合并同义准则；剔除与题干无关或无法观察的项；分配 `max_score` / `weight`；写入 `issue_tag` 建议（Q21～Q25 等）。

与现网 DEFAULT_RUBRIC 关系：默认 **D01～D04（+ 可选 D05 规范与字数）** 为骨架，LLM 填充 **每维 2～5 条** 可观察准则，而非重新发明维度名称。

### M6 标准验证（规则 + 可选 LLM #5）

| # | 验证项 | 大作文说明 |
|---|--------|------------|
| 1 | 题干约束可追溯 | 每条准则能对应题干/要求中的显式或隐含约束 |
| 2 | 范文/解析覆盖 | 参考范文中的结构/立意/论证亮点应被 Rubric 覆盖 |
| 3 | 维度一致性 | 如「论证」维不应仅含字数描述 |
| 4 | 重复/包含检测 | 同维内准则语义重复率受控 |
| 5 | 分值合理性 | Σ 维度 `max_score` = 题目总分 |

**发布门槛（建议）**：`RubricCriterion.confidence ≥ 0.85` 才进入 `published` 默认包；低于者进入 `supplementary` 或人工 review 队列。

### M7 发布与版本

- 一题多版本：`exam_standards.version` 单调递增；仅一条 `is_active=true`。
- 发布动作：写入 `questions.scoring_points` **快照**（兼容现网 API），完整对象存 JSONB。
- 回滚：切换 active 版本，无需改代码。

## 6. 置信度（V0.1-E 规则版）

沿用 V0.1 加权思路，维度调整为：

| 维度 | 权重 | 大作文含义 |
|------|------|------------|
| 来源可信度 | 30% | S/A/B/C 等级 |
| 题干/要求可追溯 | 25% | 准则能否引用题干或要求原文 |
| 范文/解析支持 | 20% | 与参考范文/解析一致程度 |
| 多模型一致性 | 15% | 第二模型对 Rubric 要点集合的 Jaccard 或人工定义一致率 |
| 维度-能力一致 | 10% | 与 A1～A5 映射是否正确 |

分级与门槛同 V0.1：**≥95% 高可信**；**85%～95% 较高**；**70%～85% 待验证**；**<70% 不进入核心评分**。

## 7. 技术选型

### 7.1 总览

| 层次 | 选型 | 说明 |
|------|------|------|
| API | **FastAPI**（现有单体） | 新增 `routers/standard_engine.py` 或 `routers/admin_standards.py` |
| 异步任务 | **Celery + Redis/现有 broker** | 与批改 Worker 可同进程异队列，或 `queue=standards` |
| 数据库 | **PostgreSQL** | 标准、资料、任务步骤；与现网一致 |
| LLM | **httpx → OpenAI 兼容** | 复用 `ai_client.py`；**不引入 LangChain/LangGraph** |
| 契约 | **Pydantic v2** | 请求/响应与 LLM JSON 解析后校验 |
| JSON Schema | 可选 `jsonschema` | 对 LLM 输出做二次校验与 CI 固定样例 |
| 文档解析 | pymupdf + python-docx + bs4 | V0.1 足够；扫描版 PDF 标记 `parse_quality=low` |
| 对象存储 | 本地卷 / MinIO（可选） | 原始文件；V0.1 可用 `uploads/` + 路径入库 |
| 前端 | **React + Ant Design**（现有） | Admin 子路由：标准任务、对比、发布 |
| 观测 | 结构化日志 + `standard_job_id` | Token 用量写入 `user_ai_usage`（call_type=`standard_gen`） |

### 7.2 为什么不选 LangChain / LangGraph（V0.1-E）

| 考量 | 结论 |
|------|------|
| 流程形态 | 固定 6～7 步 pipeline，分支少 |
| 现网资产 | 已有 `grading_service` 步骤机与 Prompt 内联模式 |
| 可测试性 | Pydantic + 纯函数验证更易单测与金样回归 |
| 演进 | 若未来出现 **多工具检索 + 人机协同审阅**，再评估 LangGraph 仅用于 **教研审阅子流程** |

### 7.3 代码布局建议

```text
services/api/app/
├── domain/
│   └── standard_engine/          # 纯领域：验证规则、置信度公式
├── schemas/
│   └── standard_engine.py        # Pydantic 契约
├── models/
│   └── standard_engine.py        # SQLAlchemy（或扩 entities.py）
├── services/
│   └── standard_engine/
│       ├── ingest_service.py
│       ├── parse_service.py
│       ├── structure_service.py
│       ├── generate_question_std.py
│       ├── generate_rubric.py
│       ├── validate_service.py
│       ├── publish_service.py
│       └── pipeline.py           # Celery 入口
└── routers/
    └── admin_standards.py
```

**依赖方向**：`standard_engine` → `ai_client`；**禁止** `grading_service` → `standard_engine` 生成逻辑（仅允许读发布 API / DB）。

### 7.4 与作答评价引擎集成

1. `essay_context.resolve_essay_context`：若 `question_id` 存在 **active standard**，Rubric 来自 `RubricStandard`；否则回退 `DEFAULT_RUBRIC_DIMENSIONS`（兼容 demo）。
2. `grading_service` 用户 Prompt 注入：`rubric_dimensions` + **可选** `loss_rules` + `focus_points`（来自 QuestionStandard）。
3. 批改 Prompt（`PromptVersion.essay_grading`）与标准生成 Prompt（新增 `PromptPurpose.standard_*`）**分表管理**。

### 7.5 安全与合规

- 资料库仅 Admin；原始解析文本含版权材料，**不** 对 C 端用户开放全文。
- LLM 调用使用教研 BYOK 或 Admin 配置；日志脱敏与现网一致。
- 发布标准不含用户数据。

## 8. 标准服务 API（M8 草案）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/admin/standards/jobs` | 任务列表 |
| POST | `/admin/standards/jobs` | 从 `question_id` 或原始资料创建任务 |

## 10. 验收指标（V0.1-E）

在 **30 道** 真实大作文上，系统自动生成标准后抽样验证（相对 V0.1 小题指标的大作文映射）：

| 指标 | V0.1-E 目标 | 说明 |
|------|-------------|------|
| 命题形式识别准确率 | ≥ 95% | 话题/命题/材料作文等 |
| 审题任务识别 | ≥ 90% | 与教研标注一致 |
| 核心 Rubric 准则召回 | ≥ 90% | 相对参考解析/范文中的 **4～6 个核心评价点** |
| 明显错误准则比例 | ≤ 10% | 与题干无关或不可观察 |
| 准则重复率 | ≤ 5% | 同维语义重复 |
| 题干追溯率 | ≥ 95% | 准则能引用题干/要求 |
| 置信度校准 | ≥ 85% | 高置信样本人工认可率 |
| 用户答案维度匹配（联调） | ≥ 90% | 与评价引擎 Prompt 06 联测 |

**North Star 指标**：核心 Rubric 准则召回 — 参考解析有 5 个核心点，系统应稳定覆盖 4～5 个，否则引擎不进入规模化导入。

## 11. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 范文版权与来源混杂 | 来源分级 + 发布包仅含准则摘要，不对外分发全文 |
| LLM 维度漂移 | 固定 D01～D05 骨架 + 校验器 3 |
| 与现网 Rubric 字段不兼容 | 发布时写 `scoring_points` 快照 + 扩展字段放 JSONB |
| 生成成本高 | 批量离线 Celery；缓存 QuestionStandard（题不变则不重跑） |
| 标准与批改 Prompt 脱节 | 单一 `question_id` 联调集；Prompt 版本与 standard version 绑定记录 |
